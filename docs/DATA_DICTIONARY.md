# POSHANLOOP — Data Dictionary

> **Version:** 1.0.0 (Prototype)  
> **Status:** Synthetic data only — no real beneficiary data  
> **All values are fictional and do not represent prevalence or clinical truth.**

---

## Overview

This document describes every data entity, field, and enumeration used in the POSHANLOOP prototype. All records in the prototype database are synthetic.

---

### TrustGateFlag

Data quality flag generated by the Trust Gate rules engine.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | String(UUID) | Primary Key | Unique flag ID |
| `measurement_id` | String(UUID) | FK → Measurement.id | Flagged measurement |
| `child_id` | String(10) | FK → Child.id | Subject child |
| `rule_code` | String(50) | Not Null | Rule identifier (see Rules table) |
| `rule_description` | String(500) | Not Null | Human-readable description |
| `severity` | String(20) | Not Null | "info", "warning", or "critical" |
| `source_field` | String(50) | Not Null | Field that triggered the flag |
| `source_value` | String(100) | Not Null | Original value |
| `recommended_action` | String(500) | Not Null | Suggested next step |
| `status` | String(30) | Not Null | See Trust Gate Statuses |
| `reviewed_by` | String(100) | Nullable | Reviewer name |
| `reviewed_at` | DateTime | Nullable | Review timestamp |
| `resolution_note` | String(500) | Nullable | Review notes |
| `created_at` | DateTime | Auto-set | Flag creation time |

#### Trust Gate Rules

| Rule Code | Description | Severity | Threshold |
|-----------|-------------|----------|-----------|
| `MISSING_DATE` | Measurement date is not recorded | warning | N/A |
| `MISSING_UNIT` | Unit of measurement is not recorded | warning | N/A |
| `INVALID_DATE` | Date is in the future or before child's expected birth | critical | N/A |
| `DUPLICATE_ENTRY` | Same child + date + type already exists | warning | N/A |
| `REPEATED_VALUE` | Identical value across consecutive measurements | info | 3 consecutive |
| `LARGE_CHANGE` | Unusually large change from previous measurement | warning | weight: 3kg, height: 5cm, MUAC: 2cm |

#### Trust Gate Statuses

| Status | Description |
|--------|-------------|
| `Clear` | No issue found or flag dismissed |
| `Needs review` | Initial state — requires attention |
| `Re-measurement requested` | Worker asked to re-measure |
| `Verified` | Reviewed and confirmed as correct |
| `Corrected` | A correction record has been created |

| `assigned_to_role` | String(20) | Nullable | Current owner role |
| `assigned_to_name` | String(100) | Nullable | Current owner name |
| `priority` | String(20) | Default: "routine" | "routine", "urgent", or "high" |
| `next_action` | String(200) | Nullable | Description of next step |

#### Case Statuses (Primary Flow)

```
New → Needs verification → Assigned → Family contacted → Barrier support arranged → Referred → Facility acknowledged → Outcome recorded → Closed
```

#### Alternative Outcomes

| Status | Description |
|--------|-------------|
| `Rescheduled` | Visit rescheduled by facility |
| `Not reached` | Family/child could not be contacted |
| `Transferred` | Case transferred to another area |
| `Cancelled` | Case cancelled with reason |
| `Escalated` | Escalated to supervisor |

#### Facility Statuses

| Status | Description |
|--------|-------------|
| `Received` | Facility received the referral |
| `Attended` | Child attended the appointment |
| `Rescheduled` | Appointment rescheduled |
| `Not reached` | Child did not attend |
| `Wrong facility` | Referral sent to wrong facility |

## Care Receipt Reference Format

- Pattern: `PL-[A-Z0-9]{5}` (e.g., PL-7K4M2)
- Generated randomly; does **not** encode any personal information
- Used as a hand-off token, **not** a national ID or proof of treatment
- Each reference is unique within the system
- Has an expiry date set at creation

## Privacy Notes

- All data in this prototype is **synthetic**
- No Aadhaar, biometric, ABHA, or real government data is used
- Names are fictional; IDs are neutral codes
- Maps/grids show **aggregate centre-level** data only — never individual locations
- Clinical decisions belong to qualified health professionals
- This data dictionary describes prototype design only; production deployment requires independent legal review
